Separate skills into two broad categories:

Questionable value
Generic frontend design skills, clean-code advice, generic debugging playbooks, instructions telling an agent to think carefully or write maintainable code. Often repeat knowledge a capable coding model already has.

Clear potential value
Internal deployment procedures, unusual API integrations, specialized compliance workflows, executable validation scripts, product-specific conventions. Provide knowledge or repeatable capabilities the model might otherwise lack.


Structure (maybe)
- The skill collection obsession. Everyone is sharing repositories full of skills promising better coding, design, planning, and productivity.
- What are we actually giving the model? Often, we're repackaging instructions the model may already understand.
- The hidden cost. More instructions can introduce conflicting guidance, unnecessary work, additional tokens, and worse outcomes.
- What the research says. Contrast the promising results from SkillsBench with the limited software engineering gains from SWE-Skills-Bench.
- When skills actually make sense. Specialized knowledge, repeatable procedures, and executable tooling.
- A better way forward. Evaluate skills like any other engineering optimization: does this improve measurable outcomes?
